## Главные правила

1. **Один источник правды — `src/data/layout.json`.** Ни одного размера комнаты или мебели
   в коде компонентов. Нужен новый параметр — добавляем в JSON (и в схему), потом читаем.
2. **Комнату не придумывать.** Нет размера в `brief.md` — спросить, а не угадать.
   Допущение, без которого не обойтись, пометить в JSON полем `"assumed": true`
   и перечислить в разделе «Допущения» брифа.
3. **Единицы:** в JSON и на 2D-чертеже — **сантиметры, целые числа**. В 3D — метры,
   перевод в одном месте (`cm → m`, ×0.01), больше нигде.
4. **Система координат плана:** начало — внутренний угол комнаты, указанный в брифе
   (обычно левый нижний на плане); X — вправо, Y — «вверх» по плану (в 3D это −Z),
   высота — Z на плане / Y в 3D. Поворот мебели — градусы по часовой, 0 = фасад «вниз» по плану.
5. **Позиция предмета — центр его габаритного прямоугольника** (x, y), плюс w (ширина
   по фасаду), d (глубина), h (высота), rot. Так проще считать повороты и проходы.
6. **Сцена лёгкая** (MacBook Air M1 и телефон): примитивы и low-poly, без тяжёлых GLB
   и HDRI, `frameloop="demand"`, `dpr` максимум 2, без реальных теней на телефоне
   (только запечённые/контактные). Бюджет: < 50k треугольников, < 100 draw calls,
   бандл < 1 МБ gzip.
7. **Фото из `input/` в git не попадают** (публичный репозиторий = чужая квартира в интернете).
   В репозиторий и на Pages — только `renders/final` после согласия друга.

## Эргономика (проверять в 2D автоматически)

| Что | Норма | Минимум |
|---|---|---|
| Основной проход (вход → окно, вход → диван) | 80–90 см | 75 см |
| Второстепенный проход (обход кресла, к стеллажу) | 60–75 см | 50 см |
| Диван ↔ журнальный стол | 40–50 см | 35 см |
| Перед распашным шкафом / комодом (ящики) | 90 см | 70 см |
| За обеденным стулом (отодвинуть и сесть) | 75–90 см | 60 см |
| Мебель ↔ батарея (по фронту) | ≥ 10–15 см | не перекрывать полностью |
| Перед окном (дотянуться до ручки, открыть створку) | зона открывания створки свободна | — |

- **Двери:** радиус открывания = ширина полотна (обычно 70–90 см). На плане рисовать дугу,
  в зону дуги + 10 см ничего не ставить. Направление открывания и петли — из брифа.
  Распашные створки окон и шкафов — так же.
- **ТВ:** расстояние глаз → экран ≈ 1–1.5 диагонали для 4K (55″ ≈ 140 см → 1.4–2.1 м),
  1.5–2.5 диагонали для Full HD. Центр экрана ≈ 100–110 см от пола (уровень глаз сидя),
  отклонение от оси дивана ≤ 30°. Окно не за спиной зрителя и не напротив экрана (блики).
- **Диван:** глубина сиденья 55–60 см, общая глубина 85–100 см; место на человека ~60 см.
- **Ковёр:** передние ножки дивана и кресел стоят на ковре, или ковёр не меньше зоны отдыха.
- **Свет:** розетки и выключатели из брифа отмечать на плане; ничего не закрывать шкафом.

Проход считается как кратчайшее расстояние между габаритами (с учётом поворота)
или габаритом и стеной; на 2D-чертеже подписывать в см, < минимума — красным.

## Экономия контекста (договорённость)

- Фото из `input/` открывать **один раз**, выписать всё нужное в `brief.md`
  (раздел «Что видно на фото»), дальше работать по брифу, а не по картинкам.
- `layout.json` целиком не перечитывать без нужды: менять точечно (Edit/скрипт),
  читать нужный кусок через `jq`.
- Не выводить в чат большие файлы, сборочные логи — только хвост с ошибкой.
- Скриншоты сцены — только когда проверяем визуал, в уменьшенном масштабе.
- Состояние проекта держать в разделе «Статус» этого файла, а не пересказывать в чате.
- Ответы короткие: что сделано, что проверить, что дальше.

## Стек (решено 20.11.2026)

Vite 8 + React 19 + TypeScript, `@react-three/fiber` 9 для 3D (drei не нужен: OrbitControls берём из three),
**2D-чертёж — SVG** из того же JSON (не ортокамера three.js: точные подписи, чёткость
на телефоне, лёгкий экспорт), `zod` для проверки `layout.json`, состояние вида —
в URL-хэше (`#v=B&cam=sofa&pal=warm`), чтобы делиться конкретным видом ссылкой.
Деплой — GitHub Actions → Pages, `base: '/living-room/'` в `vite.config.ts`.

Запуск: `npm run dev` (порт 5174 в превью Claude), сборка `npm run build` = check + tsc + vite.
Сборка 20.11: интерфейс 82 КБ gzip, 3D-кусок 252 КБ gzip (грузится лениво).

### Как устроена сцена (чтобы не перечитывать код)
- Материалы выдаются по ролям (`walls`, `textile`, `wood`…) из `prims.tsx`; режим снимка меняет
  все материалы разом: глина — один серый, линии — белый + рёбра `EdgesGeometry`, глубина — свой шейдер.
- «Кукольный дом»: стена прячется, если камера снаружи её внутренней грани (`updateWalls`).
- Снимок: временно `setSize(1536, 1024)` → `render` → `toDataURL` → вернуть размер.
  В dev из консоли доступен `window.__capture.current.capture(preset|null, w, h)`.
- Угол обзора пресета вертикальный; на портретном экране он пересчитывается в горизонтальный.

## Формат layout.json (черновик, уточнить после брифа)

```jsonc
{
  "meta": { "units": "cm", "origin": "угол у входа", "version": 1 },
  "room": {
    "height": 270,
    "outline": [[0,0],[420,0],[420,560],[0,560]],   // внутренний контур по часовой
    "wallThickness": { "default": 12, "byWall": { "1": 40 } },
    "openings": [   // привязка к стене: номер ребра контура + отступ от его начала
      { "id": "O1", "type": "window", "wall": 1, "offset": 110, "width": 150,
        "sill": 85, "height": 145, "swing": { "side": "left", "into": "room" } },
      { "id": "D1", "type": "door", "wall": 3, "offset": 20, "width": 80,
        "height": 205, "swing": { "hinge": "right", "into": "room" } }
    ],
    "fixtures": [ { "id": "R1", "type": "radiator", "wall": 1, "offset": 120,
                    "w": 100, "d": 10, "h": 60, "z": 10 } ]
  },
  "catalog": {    // мебель описана один раз
    "sofa3": { "name": "Диван 3-местный", "w": 220, "d": 95, "h": 85, "shape": "sofa" }
  },
  "variants": [   // варианты только расставляют предметы каталога
    { "id": "A", "name": "ТВ у глухой стены",
      "items": [ { "ref": "sofa3", "x": 210, "y": 120, "rot": 0 } ] }
  ],
  "palettes": [ { "id": "warm", "walls": "#e8e1d6", "floor": "#b08a62",
                  "materials": { "sofa3": "#6b7a6a" } } ],
  "cameras": [ { "id": "entry", "pos": [40, 520, 150], "target": [300, 100, 110], "fov": 60 } ]
}
```

Проходы и нарушения не храним — считаем из геометрии при отрисовке.
